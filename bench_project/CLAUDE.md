# BioStatBench — working rules

This repository is a benchmark. Its value depends entirely on the answer keys staying
secret from the systems being measured and on results being re-derivable. Both are easy
to destroy by accident.

## Hard rules

1. **Never read, print, summarise, or `grep` anything under `_keys/` or `items/private/`.**
   Not to "check an answer", not to "verify consistency". If a task seems to need it, stop
   and say so.
2. **Never write an answer key by hand for a code item.** Keys for `T3_code` and
   `T7_agentic` are generated by executing the reference solution in the pinned
   environment (`/bsb-key`). A typed key is unverifiable and will eventually be wrong.
3. **Never paste proprietary, unblinded, or patient-level trial data into an item.** Use
   the public sources listed in `protocol/BENCHMARK_PROTOCOL.md` §9. If an item stem
   needs a study identifier, invent one.
4. **Never commit anything under `items/private/`.** It is gitignored; do not override.
5. **Model identifiers are pinned to what this gateway actually resolves stably, and recorded
   with `claude --version`.** On the public API, that means full names, never aliases
   (aliases float). **On the Lilly Code gateway this is inverted, confirmed by direct test**:
   requesting a public full name like `claude-sonnet-5` gets silently substituted with a
   `system/informational` warning ("restricted by your organization's settings"), while
   `opus-latest`/`sonnet-latest`/`haiku-latest` each route cleanly to a stable, distinct
   model. Use the three `-latest` aliases as `--models` here — see
   `protocol/ADDENDUM_A_claude_code.md` §A.3 and `harness/cc_runner.py`'s `PINNED_MODELS`.
6. **Never add `--fallback-model` to a scored run.** Silent substitution to another model
   destroys attribution: you would record a score against a model that did not produce it.

Rules 1 and 4 are stated here for humans and for Claude, but `CLAUDE.md` is guidance, not
enforcement. Enforcement is `.claude/settings.json` deny rules plus filesystem
permissions. Treat the settings file as the boundary and this file as the explanation.

`.claude/settings.json` in this directory denies `Read`/`Grep`/`Glob` on `_keys/**` and
`items/private/**`, plus best-effort `Bash` patterns for the same paths. This stops
Claude Code's own tool calls in *this* interactive session — it is not a security
boundary against a determined agent (a Bash one-liner using an environment variable or
a symlink to route around the literal deny pattern is not caught) and it does not apply
at all under `--bare`, which `cc_runner.py` uses for every scored run (see
`protocol/ADDENDUM_A_claude_code.md` §A.5). The real boundary for scored runs is that the
workspace `cc_runner.py` builds never contains the keys in the first place; this
settings file exists to stop the *authoring* session from accidentally reading them,
not to contain an adversarial one.

## Layout

```
protocol/      protocol and addenda (the "why")
items/         item bank; items/private/ is gitignored
_keys/         answer keys and test scripts — OFF LIMITS to any agent run
harness/       run_bench.py (API surface), cc_runner.py (Claude Code surface)
analysis/      scoring_and_inference.R, factorial_analysis.R, verify_*.py
```

## Conventions

- Item IDs are `D<domain>-<TAG>-<nnn>` and are never reused after retirement.
- Every rubric criterion carries a severity (S1/S2/S3) and a provenance string. A
  criterion with no provenance is an opinion and does not belong in the bank.
- Every numeric key carries a `derivation` field that a reviewer can re-run.
- R code targets the pinned `renv.lock`; do not add a dependency without updating it.
